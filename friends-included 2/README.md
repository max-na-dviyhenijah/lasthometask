# Friends Included finance

English-language coursework application for **Maksims Paņuškins**.

One Telegram bot, a Supabase ledger, a Vercel website and an automatically updated Google Sheets copy. No AI model, paid AI API or runtime package dependency is required.

## Current status

The application code is implemented and locally tested. The live Telegram bot, Supabase project, Google service account, spreadsheet, GitHub repository and Vercel deployment still need to be connected. **Do not submit the local preview as completed coursework.** S01 and E01 must be entered through the actual Telegram bot after setup.

Start with [the connection guide](docs/SETUP.md), then follow [the exact coursework test sequence](docs/COURSEWORK-TESTS.md). The local test results and remaining live checks are recorded in [verification](docs/VERIFICATION.md).

## Put this folder on GitHub

Use **this `friends-included` folder as the repository root**. It contains `package.json`, `vercel.json`, `api/`, `public/`, `src/`, `supabase/` and the instructions. Do not upload the whole Accounting folder. Do not upload `.env.local`, private keys, `.local`, `node_modules` or unrelated documents.

Create the GitHub repository, upload the project files including the `.gitignore` file, then import that repository into Vercel. The GitHub repository link can be added to the app through `PUBLIC_GITHUB_URL`.

## Local preview

Install Node.js 22.9 or later (Node.js 24 LTS recommended). From this folder:

```sh
npm run preview
```

Open http://127.0.0.1:4173. The preview uses the two homework scenarios in memory, displays the expected cumulative results, and allows additional fictional transactions. It is clearly marked **Local preview**. Restarting clears local changes. It never connects to Telegram, Supabase or Sheets and is disabled on Vercel.

For an empty local preview:

```sh
LOCAL_DEMO=true npm run dev
```

For the real Supabase-backed app, copy `.env.example` to `.env.local`, fill the values privately, keep `LOCAL_DEMO=false`, and run `npm run dev`.

## Verify

```sh
npm test

```

Optional PostgreSQL validation using the development-only PGlite package:

```sh
npm install --no-save @electric-sql/pglite@0.5.8
node scripts/verify-database.mjs
```

This extra package is not required to run or deploy the application.

## Main rules

- Sales are pending until Svetlana approves the sale and its commission split.
- Commission is 10% of an approved sale. Percentages divide that pool and must total exactly 100%.
- Every expense reduces company result immediately. Project expenses await allocation; overhead is allocated automatically.
- Original proposals are immutable. Decisions update existing records, not additional transactions.
- Website and Telegram actions use the same `FinanceService` and calculation functions.
- Staff can submit and view their own entries. Only Svetlana can approve or allocate.
- The website intentionally exposes fictional demonstration roles. It is not an authentication system for real company finances.

## Structure

| Folder | Purpose |
|---|---|
| `public/` | English interface, responsive layout, forms and dashboard |
| `api/` | Vercel HTTP functions for website actions and Telegram webhook |
| `src/` | Shared rules, Supabase access, bot handling and delivery queue |
| `supabase/` | Database installation script, permissions and atomic update functions |
| `scripts/` | Preview, build, configuration check and bot setup |
| `tests/` | Business rules, permissions, integration recovery and example records |
| `docs/` | Connection instructions, test sequence, architecture and verification |

`dist/` is generated by the build and is not source code. No completed live integration is claimed until the checks in the guide have been performed.
